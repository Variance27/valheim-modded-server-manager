# Troubleshooting

Fixes for problems seen in real use. Commands run on the VPS unless stated.

## The server is running but "ValheimEnforcer loaded" and "Mods.yaml present" stay red

Look at `BepInEx/LogOutput.log` in the game folder:

```bash
sudo grep -n -i -E "enforcer|error|missing|dependenc" /home/vhserver/serverfiles/BepInEx/LogOutput.log | head
```

- **`... has missing dependencies: com.jotunn.jotunn`**: Enforcer's dependencies are not installed. Run Setup step 6 again (it installs them), then Stop and Start.
- **No BepInEx log at all**: BepInEx is not being injected. Check that `common.cfg` has the four `DOORSTOP_*` / `LD_*` lines (Setup step 5) and that the server was started after they were added: `sudo tr '\0' '\n' < /proc/$(pgrep -u vhserver valheim_server)/environ | grep -E "DOORSTOP|LD_PRELOAD"`.

## "Non-allowed mods found: com.ValheimModding.NewtonsoftJsonDetector"

Your client has JsonDotNET but the server does not, and ValheimEnforcer rejects mods the server does not list. Either remove JsonDotNET from the player's profile, or install it on the server (Mods tab) and restart. Codes generated by current versions only include JsonDotNET when the server has it. Re-run Setup step 7 to update `generate-codes.py` on the VPS, regenerate the code, and re-import it.

More generally, "Non-allowed mods" means the client has a mod that is not in the server's Required, Optional or Admin lists. The error screen names the mod's GUID.

## Players cannot join

1. Is the process up? `sudo pgrep -u vhserver -a valheim_server`
2. Are the UDP ports open? A world uses its port and the next two (2456-2458 for the first world). The GUI opens them in `ufw` for you (Setup step 3 and step 8; the checklist has a "Firewall allows the game ports" item), so check `sudo ufw status verbose` to see the rule. A firewall in your provider's panel is separate and must be opened there.
3. Test with **Join by IP** (`<VPS IP>:2456`). A server can be reachable while the server browser still takes minutes to list it.
4. Do the versions match? The error screen shows the local and remote Valheim and mod versions.

## Backup fails with `__LGSM_HOME__: No such file or directory`

An unrendered script template reached the VPS (a repo copy was uploaded by hand). Run Setup step 7 again, or restore the original from the `.bak.<timestamp>` copy. To check: `grep -l "__LGSM_\|__SERVER_DIR__" /home/vhserver/scripts/*`.

## Off-site backups do not run

`CLOUD_REMOTE` must be set in `/home/vhserver/.config/valheim-notify.conf`, for example `CLOUD_REMOTE=MyRemote:Valheim-Backups`, and the rclone remote must exist for the game account. Without it, backups stay on the VPS by design.

## Start fails with "Ownership issues found"

LinuxGSM refuses to start if files under its folders are owned by root. The GUI fixes the ownership and retries once on its own. By hand: `sudo chown -R vhserver:vhserver /home/vhserver`.

## `vhserver check-update` says SteamCMD is not installed

On a server using the distribution's `steamcmd` package, LinuxGSM's own `check-update` may print "SteamCMD is not installed", extract its own copy, and then fail the remote-build check, even though the game runs fine. The cause was not identified, and running SteamCMD once as the game account (`sudo -u vhserver bash -c 'cd /home/vhserver/.steam/steamcmd && ./steamcmd.sh +quit'`) completed its first-time setup but did not make that check pass.

The GUI's **Updates** tab uses its own script (`check-valheim-update.sh`), which asks Steam directly. On one server it also failed with `could not determine latest buildid from Steam` although `app_info_print 896660` worked by hand. The script now tries three times and, if it still fails, prints the last lines SteamCMD printed so the cause is visible. Re-run Setup step 7 to deploy the new script, then use **Check now** and read that output: a connection error means Steam or the network, an empty output means `sudo -u <game account>` is not working without a password. The cause on that server was Debian's `/usr/games/steamcmd` wrapper, which tried to run `~/.steam/steamcmd/steamcmd.sh` in the game account's home and found nothing (`exec: ... steamcmd.sh: not found`). The script now prefers the SteamCMD copies LinuxGSM keeps in that home and falls back to the distro wrapper only if none exist, trying each in turn.

## Setup says the OS is not supported

The Setup tab supports Ubuntu and Debian only. On another distribution, install LinuxGSM by hand and use the later steps (BepInEx onward).

## I forgot the GUI password

Delete `auth.json` next to `server.js` and restart the GUI. A new random password is printed once. Or run `node set-password.js`.

## Mods tab shows a wrong update badge

Pick the right source in the update prompt, or set a pin from the mod's row. See [how matching works](MODS_AND_ENFORCER.md#how-a-folder-is-matched-to-a-modsyaml-entry-and-a-package). Use **Ignore Updates** for a mod that is not worth a reminder.

## Still stuck

Open an issue with the step or tab, the exact error text, and the relevant lines from `LogOutput.log` or the step's output box. **Remove passwords, webhook URLs and IP addresses first.**
